🛑 The 5 checkpoints — where you take over

These are decision gates, not just progress markers. At each one I stop, hand you the freshly built artifacts, and wait for your sign-off before touching anything downstream. Full checklist versions appear inline in the roadmap below.

CP-1

Foundation contracts

After Step 3 · end of Phase 1

Approve the tool signature (handler(kwargs)→str), the 3-tier permission map, and the bash command classification list.

CP-2

Model prompts & heuristics

After Step 8 · before the engine

Review the real system-prompt scaffold text, the context-compaction heuristic, and the 3 sub-agent preset prompts.

CP-3

Model scope

After Step 9 · before the loop

Decide: offline DummyModel only, or also wire the optional OpenAI client now?

CP-4

Demo sign-off

After Step 13 · before hardening

Confirm the planted bug, the agent.md instructions, goal copy, and offline vs live demo cadence.

CP-5

Final acceptance

After step 19 · end of Phase 5

Everything green — you explore the demo and packaging yourself, sign off, and we close the loop.

🛑 Checkpoint 01Gate · after Step 3 — before Phase 2

You verify — the foundation contracts

  • handler(kwargs: dict) → str — is this the tool API you want exposed to the model?
  • Permission tiers read < workspace < full and the >= allow rule
  • The bash classification sets (ls/cat → read · rm/sudo → full · everything else → workspace)
  • The five primitives and their exact signatures — these are stable forever from here on
Why pause hereThis is the boot layer. The Harness loop (Step 10) and the whole test suite (Step 15) are built directly on these contracts. A signature change now costs one edit; the same change after Step 10 touches the loop, hooks, model, and every test file.

Phase 03 · Core engine + skill layer
9
Phase 3 · Buildharness/model.py
Model protocol + offline DummyModel
Model protocol · end_turn()/tool_call() builders
  • DummyModel is scripted & deterministic — tests and the demo run with zero API keys
  • Optional OpenAIModel exists but only activates when openai is installed and OPENAI_API_KEY is set
🛑 Checkpoint 03Gate · after Step 9 — before the loop

You decide — model scope

  • Option A (default): offline DummyModel only — zero keys, fully scripted, enough to prove the harness end-to-end.
  • Option B: also wire OpenAIModel now — enables live runs but adds a runtime dependency and needs a key in your environment.
  • Either way the Model protocol stays identical, so this is a cheap toggle — but it shapes what Step 13's demo attempts.
Why pause hereThis is the one point where adding a live provider is cheapest. If we build the demo (Step 13) as offline-only and you later want live, it's an add-on rather than a rebuild — but you may also prefer to keep the repo dependency-free forever. Decisions like that are yours.
10
Phase 3 · Buildharness/loop.py
The engine — Harness class & run loop
Harness(model, cwd, max_iterations=10, ...) · decide → dispatch → feedback
  • run(goal) assembles the prompt, seeds the goal, iterates, returns on end_turn
  • _dispatch_tool: permission gate → pre-hooks → handler → post-hooks → persist
  • Unknown tool / denied call → error string, loop survives

  • Set __version__ = "0.1.0"
